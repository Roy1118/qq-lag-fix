# 那几个 Chromium 开关在做什么

写给"想知道为什么这么改"的人。不了解原理也能用——`scripts/apply-fix.ps1` 会替你写进去——
但理解了才能在没效果时判断下一步往哪走。

## 背景：为什么 Electron 应用会"字迟到"

Electron 应用的界面不是用 Win32 控件画的，而是**整个内容区当作一块 GPU 合成的画布**。
输入框里那个光标和文字，是 Chromium 渲染出来的一帧图像，不是系统原生控件。

所以从"你敲下键盘"到"你看见字"，要走完整条链：

```
键盘事件 → 输入法(TSF) → Chromium 渲染进程生成帧 → GPU 进程合成 → DWM 合成 → 屏幕
```

**任何一环被降级，都会表现成"字打完了半秒才出来"。** 而不是"输入法坏了"或"QQ 有 bug"。

## Chromium 的窗口节流优化

Chromium 为了省电，会判断"这个窗口是不是被挡住了/在后台"，如果是就降低帧生成频率。
这在浏览器里很合理——一个被挡住的标签页不需要每秒画 60 帧。

判定机制叫 **native window occlusion calculation**（原生窗口遮挡计算）：
Chromium 通过 Win32 API 问系统"我这个窗口可见吗"。

问题出在这里：**在混合显卡 + 虚拟显示适配器的机器上，这个判定经常判错。**
Windows 自己也在用 DWM 的遮挡信息做优化，虚拟显示器会让它算不准。
结果是：**窗口明明在你眼前，Chromium 却以为它在后台，于是按后台节奏出帧。**

你打字，字就慢半拍。

## 三个开关

### `--disable-features=CalculateNativeWinOcclusion`

关掉"原生窗口遮挡计算"这个特性。Chromium 不再问系统"我被挡住了吗"，
而是自己保守地认为"我可见"。

**这是三个里最直接对应症状的一个。** 如果你的问题是"打字延迟"，优先试它。

### `--disable-backgrounding-occluded-windows`

即使 Chromium 认为窗口被遮挡了，也**不要**把它降级成后台窗口
（后台窗口的渲染优先级、定时器精度都会降）。

和上一个配合：上一个让它别判错，这一个让它在判错时也别降级。

### `--disable-renderer-backgrounding`

不让 Chromium 降低"处于后台的渲染进程"的进程优先级。
作用在前两个之上——即使窗口真的在后台，也别把渲染进程的 CPU 优先级压下去。

## 代价（必须告诉用户）

关掉这些节流之后，**QQ 被遮住或最小化时仍然会按前台节奏渲染**。

- 笔记本上会多耗一点电（GPU 和 CPU 都有）
- 多占一点 GPU 时间

对一个聊天软件来说通常可以接受——你不会同时开八个 QQ 窗口。
但如果用户特别在意续航，可以只用 `-NoOcclusionFlags` 跳过关开关这一项，
只做 GPU 偏好调整。

## 什么情况下不该用这些开关

- **`--disable-gpu`** —— 别用。它关掉整个 GPU 加速，会让 QQNT 退回软件渲染
  （更慢），而且 NapCatQQ issue #1332 记录过 QQNT 在 GPU 初始化失败时
  直接起不来、拿不到登录二维码。要用也用 `--disable-gpu-compositing`，别用 `--disable-gpu`。
- **问题不在渲染路径时** —— 如果用户说的是"QQ 发消息要转圈很久"（网络）、
  "QQ 启动要 30 秒"（磁盘/启动项）、"QQ 打不开"（另一回事），这些开关帮不上忙。
  先确认症状是**渲染/输入回显**类，再动。

## 怎么验证开关真的生效了

别假设。启动 QQ 之后直接读子进程的命令行：

```powershell
Get-CimInstance Win32_Process -Filter "Name='QQ.exe'" |
  ForEach-Object { "PID $($_.ProcessId)  $($_.CommandLine)" }
```

主进程应该能看到完整开关列表，渲染进程（`--type=renderer`）通常也能看到
（Chromium 会把 feature 列表传给子进程）。

**如果读不到**，说明透传失败，得换思路——可能是启动器壳没有转发参数，
那就得考虑在快捷方式上直接加参数，或者干脆放弃这条路。

## 为什么必须写进三个入口

QQ 有三个常见的启动路径，缺一个用户下次从那里启动就白搭：

1. **开机自启** —— `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `QQNT` 值
2. **开始菜单快捷方式** —— 用户从开始菜单点的时候
3. **桌面快捷方式** —— 用户双击桌面图标的时候

（任务栏固定项也要，但它的路径随 Windows 版本变化，`apply-fix.ps1` 会一起搜。）

漏掉入口的表现是：**"有时候好有时候不好"** —— 因为用户是从不同地方启动的。
这种间歇性现象最容易让人怀疑"是不是我改的东西没用"。
